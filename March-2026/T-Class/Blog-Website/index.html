What are Arrow Functions?

Arrow functions are a shorter, more modern way to write functions in JavaScript, introduced in ES6 (2015). They let you express the same logic with less code — no function keyword, cleaner syntax, and often no need for return.

Think of them as a streamlined version of the functions you already know. Same idea, different (better) outfit.

💡 Why they matter

Arrow functions are everywhere in modern JavaScript — inside map(), filter(), setTimeout(), React components, and more. You'll read and write them daily.

Handling Parameters

Arrow functions have a clean shorthand rule for parameters: with exactly one parameter, you can drop the parentheses. Zero or two-or-more still need them.

javascript
// No parameters — keep the ()
const sayHi = () => "Hi there!";

// One parameter — parens are optional
const square = n => n * n;
const shout = word => word.toUpperCase();

// Multiple parameters — must use ()
const add = (a, b) => a + b;
const fullName = (first, last) => `${first} ${last}`;
✏️ Style tip

Many teams prefer to always keep parentheses around parameters — even single ones — for consistency. Both styles are valid. Pick one and stick with it.

Implicit vs Explicit Return

This is where arrow functions get truly powerful. When your function body is a single expression, you can remove the curly braces and the return keyword — JavaScript returns it automatically. That's called an implicit return.

Explicit return
const double = n => {
  return n * 2;
};

// Curly braces present
// return keyword needed
Implicit return
const double = n => n * 2;


// No curly braces
// No return keyword

More examples of implicit return in action:

javascript
const greet = name => `Hello, ${name}!`;
const isEven = n => n % 2 === 0;
const cube = n => n * n * n;
const add = (a, b) => a + b;

// Use explicit return for multi-line logic:
const classify = n => {
  if (n > 0) return "positive";
  if (n < 0) return "negative";
  return "zero";
};
⚠️ Object literal gotcha

Returning an object with implicit return? Wrap it in parentheses, or JS will confuse {} for a function body: const getUser = () => ({ name: "Shivam" })

Arrow vs Normal Functions

For now, the most practical difference comes down to syntax and style. Arrow functions are not just "shorter functions" — they're a different thing, but at this stage, focus on the readability win:

javascript — side by side
// ——— Normal function ———
function multiply(a, b) {
  return a * b;
}

// ——— Arrow function ———
const multiply = (a, b) => a * b;

// Both are called the same way:
multiply(3, 4); // → 12

Key differences at a glance (deeper ones like this binding come later):

Normal Function
Uses function keyword
Can be hoisted (used before declared)
Works as constructor (new)
Has its own this context
More verbose, very explicit
Arrow Function
Uses => syntax
Not hoisted (must define first)
Cannot be a constructor
No own this (inherits from parent)
Concise, modern, readable
📌 Rule of thumb

Use arrow functions for short callbacks and one-liners. Use regular functions when you need hoisting, a named function for recursion, or you'll learn about this later — arrow functions behave differently there.
